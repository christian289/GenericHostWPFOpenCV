Native Linux build (amd64 CPU)

From the src/OhMyRudolph directory, using the configured local Podman machine:

  podman --connection podman-machine-default build --network=host --platform linux/amd64 --target native -f native/OhMyRudolph.Native/Containerfile.native -t localhost/ohmyrudolph-native-build:local .

The builder runs the upstream CPU Hello World and native_smoke; an unsuccessful command fails the image build. The final scratch image contains /app/libohmyrudolph_native.so, both models under /app/mediapipe/modules, /app/licenses/mediapipe-LICENSE, native_smoke and native-ldd.txt. Integrators can COPY --from=<native image> /app/ /app/ into a runtime image. Run native_smoke with /app as its argument and LD_LIBRARY_PATH=/app; do not use the scratch image itself as a runtime. Inspect native-ldd.txt in the actual build and install every listed system library in the runtime; Ubuntu 24.04 build uses the system C/C++ runtimes, libjpeg and OpenCV 4. A runtime based on another distro/release needs compatible sonames, libstdc++, and glibc. No Python or Bazel is required at runtime.

Provenance: MediaPipe v0.10.21 tag resolves to cad7f3ab99ebf175947e40c5252c642612aae927; upstream .bazelversion is 6.5.0. Bazel 6.5.0 Linux x86-64 is verified against SHA-256 a40ac69263440761199fcb8da47ad4e3f328cbe79ffbf4ecc14e5ba252857307. Compiler is Ubuntu 24.04's distribution default GCC (normally GCC 13). The pinned MediaPipe XNNPACK commit dc1549a7141c7a9496ae160bb27b8700f0f6e1f1 compiles AVX-VNNI-INT8 microkernels with -mavxvnniint8, which GCC first documents in its GCC 13 release notes; Ubuntu 22.04's GCC 11 rejects that option. These kernels use XNNPACK's runtime dispatch and do not make AVX-VNNI-INT8 a baseline CPU requirement. Ubuntu 24.04 tag and apt versions are not digest/snapshot pinned; this recipe is version-directed but not a bit-reproducible build. Bazel also fetches upstream's declared transitive dependencies. Record resolved image and package versions when building.

Model source is the official MediaPipe 0.10.21 PyPI manylinux x86-64 wheel, verified before extraction by fetch_models.py; it verifies both model hashes too. Wheel metadata declares Apache 2.0 and its bundled LICENSE is copied with the models. Face detection SHA-256 bbff11cebd1eb27a1e004cae0b0e63ec8c551cbf34a4451148b4908b8db3eca8; landmark SHA-256 1055cb9d4a9ca8b8c688902a3a5194311138ba256bcc94e336d8373a5f30c814. URL and wheel hash are in fetch_models.py.

The smoke program covers missing resources, repeated create/destroy, synthetic no-face JPEG, invalid JPEG and dimension mismatch. It does not contain a positive face fixture and a successful default smoke is not proof that a face can be detected. A separately licensed and checksum-verified positive JPEG fixture can be tested using `LD_LIBRARY_PATH=/app /app/native_smoke /app /path/to/fixture.jpg WIDTH HEIGHT`; this additionally checks positive inference and insufficient capacity. No photographs or coordinates are written by this program.

The API allows one active call per handle and destroy only after that call ends. Resource roots are absolute UTF-8 Linux paths; MediaPipe's per-graph resource mapping avoids a global working-directory or environment-variable dependency. Per-frame tracking is disabled, with five faces and landmark 1. Coordinate conversion matches the prior Python implementation (truncation, no clamping). Image dimensions are limited to 4096 each and 16,777,216 pixels; the libjpeg header is validated before allocating decoded pixels.
